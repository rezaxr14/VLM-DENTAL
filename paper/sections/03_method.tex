\section{\sys{}: System and Method}
\label{sec:method}

This section describes the system from the inside out. We first fix the task and the agent loop
(\cref{sec:setup}), then the architecture around it: the data, the model, and which parts are trained
(\cref{sec:architecture}). The tool suite (\cref{sec:tools}) and the self-correcting tool \texttt{nudge\_crop}
(\cref{sec:nudge}) are the interface through which the agent looks at an image again; the tiered perturbation
(\cref{sec:perturbation}) is how demonstrations learn to use that interface skeptically. \cref{sec:traces}
describes how the demonstrations are generated, verified, and cleaned, \cref{sec:traceanatomy} follows one
trace through both arms of the corpus, and \cref{sec:reward} describes the two training stages and the reward.

\subsection{Problem setup and agent loop}
\label{sec:setup}

An OPG $I$ is annotated as a \emph{set} of findings $F = \{f_1, \dots, f_m\}$ (possibly empty for
a healthy image), where each finding $f = (\text{quadrant}, \text{tooth position},
\text{diagnosis})$ uses FDI two-digit notation over DENTEX's four diagnosis classes
(caries, deep caries, periapical lesion, impacted tooth). The agent receives the image and a
registry of tools, and produces a sequence of turns; each turn contains free-form clinical
reasoning and zero or more structured tool calls, and the loop ends with a structured final
answer reporting \emph{every} finding the agent commits to. The same agent loop is used for
synthetic data generation, RL rollouts, and evaluation, and tool calls execute for real against
the source image at every stage (\cref{fig:overview}). Tool calls are capped at 50 per episode, and a
lightweight JSON extractor repairs truncated or markdown-wrapped outputs.
Throughout the paper the \emph{agent} is the model that runs this loop at inference time and during RL rollouts, the
\emph{teacher} is the frontier model that generates demonstrations offline, and the \emph{verifier} audits those
demonstrations.


\subsection{System architecture}
\label{sec:architecture}

\cref{fig:overview} shows the complete system: the agent loop used at inference and evaluation time, and the offline
stack that produces its weights. Four component groups surround one agent core --- a Qwen3.5-9B vision-language
model running the loop of \cref{sec:setup}: a data layer (\cref{fig:data}: registry-driven loaders for the two in-use
sources, DENTEX and Tufts; a candidate pool of eight further public panoramic datasets, promoted only after their
annotation semantics are verified), the trace synthesis stack of \cref{sec:traces}, the two training stages of
\cref{sec:reward}, and an evaluation layer (\cref{sec:eval}) whose probes feed model selection on a fixed dev split.

\cref{fig:internals} opens the model. Qwen3.5-9B has a 27-block vision transformer (frozen), a two-layer merger
(trained), and 32 text layers: 24 Gated DeltaNet layers and 8 full-attention layers in a 3:1 pattern, each followed by an
MLP, over a 4-bit NF4 base (QLoRA). Training adds LoRA \citep{hu2022lora} to the attention, DeltaNet and MLP projections; the optional speculative-decoding extension
(\cref{sec:specdecode}) also fine-tunes the native multi-token-prediction (MTP) block. Embeddings, norms,
convolutions and \texttt{lm\_head} stay frozen.

Three single-source-of-truth decisions hold the system together. First, one shared dispatcher
defines, for every tool, whether and \emph{which} image it consumes --- always the native source
image --- so the trace-generation loop, the GRPO rollout loop, and the evaluation runner cannot
silently diverge. Second, the image-input geometry lives in one module and is an explicit
flag, not an implicit behavior. The model sees aspect-preserving views of the image and of each crop (canonical
sizes of $1536{\times}768$ for the full image, $256{\times}384$ for crops, and $512{\times}384$ for
side-by-side comparisons), while every tool operates on the native image, so all coordinates remain in native pixels and
the coordinates the model was trained to emit stay valid at inference. The views keep the aspect ratio and
add no padding.
Third, the conversion from DENTEX's zero-indexed annotation rows
to FDI notation has exactly one implementation, called by the reward, the verifier, and the
metrics alike --- so an indexing error cannot arise independently in several subsystems.


\subsection{A tool suite with continuous parameters}
\label{sec:tools}

The registry exposes eight tools (\cref{tab:tools}; \cref{fig:tools} shows what they return). The deliberate design choice throughout is
that tools expose \emph{how much} effect to apply as a continuous or overridable parameter, not
just a fixed on/off call: denoising takes a continuous \texttt{strength}, windowing takes exact
\texttt{center}/\texttt{width} values as an override on top of tissue presets, contrast takes a
multiplicative \texttt{factor}, and cropping takes a tunable context margin. An agent calling \texttt{denoise(strength=0.3)}
rather than \texttt{denoise(strength=0.9)} is expressing a patient-specific judgment about how
grainy a crop is. A fixed three-level menu cannot carry this information, and the resulting
tool-call stream is more informative to train on and to audit.

\subsection{Self-correcting grounding: \texttt{nudge\_crop}}
\label{sec:nudge}

The grounding tool is a YOLOv8m detector \citep{jocher2023yolov8} (one class per FDI quadrant--position pair) fine-tuned on
2{,}339 DENTEX+Tufts images with 46{,}808 tooth boxes, with 5-fold cross-validation (\cref{fig:data}; per-fold numbers in
\cref{app:grounding}). It is a tool that grounds the agent, not a contribution of this work: the folds are close to each
other (mean \emph{target} mAP50 0.951 for DENTEX-only and 0.938 with Tufts), so which fold is used makes no real
difference. It is still a 32-class detector, and its errors propagate into downstream reasoning: a box shifted by half
a tooth-width yields a crop that still \emph{looks} like a plausible anatomical region while showing the wrong tooth.

\texttt{nudge\_crop} makes such errors correctable. It takes a box the agent was
\emph{already given} (by \texttt{locate\_tooth} or a previous \texttt{nudge\_crop}; it cannot
create a box from scratch) and returns adjusted coordinates: a shift $(\texttt{dx\_frac},
\texttt{dy\_frac})$ expressed as fractions of the box's own width and height, and a rescale
\texttt{scale} around the new center, clamped to image bounds. The tool is deliberately
\emph{data-only}: it computes coordinates, and the agent must pair it with \texttt{zoom\_crop}
to actually see the corrected region. Two consequences follow. First, a fractional,
box-relative parameterization (``shift left by about half the box'') is easier for a VLM to
reason about than raw pixel coordinates at an arbitrary zoom level. Second, because
each correction must be followed by a verification crop, the loop enforces an
inspect--correct--re-inspect cycle rather than a single blind adjustment. To our knowledge, neither
concurrent dental agentic system exposes such a mechanism: their tools are fixed operations
whose outputs the agent can only accept.

\subsection{Tiered perturbation: making self-correction learnable}
\label{sec:perturbation}

An agent learns to question its tools only if its demonstrations do. An idealized
demonstrator, whose grounding tool always returns the right box, demonstrates
\emph{trusting} the tool, and SFT on such traces teaches the wrong reflex. At the same time, unguided exploration by the demonstrator would sharply reduce the yield of
usable traces.

Our resolution (\cref{fig:mechanism}) separates what the grounding tool \emph{computes} from
what the demonstrator \emph{sees}. During trace generation, \texttt{locate\_tooth} operates in a
ground-truth-grounding mode: for an annotated tooth it returns the expert-verified box
(guaranteeing the demonstration remains solvable), while for exploratory calls on unannotated
teeth it falls back to real detector inference. Then, independently of how the box was obtained,
a \emph{perturbation roll} decides what is displayed (exact configuration in
\cref{app:perturbation}):

\begin{itemize}[leftmargin=*,itemsep=1pt,topsep=2pt]
  \item \textbf{none} (45\%): the box is shown as computed, giving a clean accept-and-proceed demonstration;
  \item \textbf{small} (25\%): a synthetic offset of 12--28\% of the box's own size per axis,
  random sign. This is a judgment call that the zoom margin often absorbs, and the
  prompt does \emph{not} say whether such a box needs correction;
  \item \textbf{big} (30\%): an offset of 45--75\% per axis, sized to be visually self-evident.
\end{itemize}

Offsets are applied with \texttt{nudge\_crop}'s own shift-and-clamp math, so every perturbed box
is one the correction tool could plausibly have produced or fixed; the unperturbed box is logged
internally for auditing but never shown. Two design choices matter more than the specific rates:

\paragraph{Fixed rates, decoupled from detector accuracy.}
The perturbation probabilities are configured constants, not a reflection of the grounding
model's measured error rate. This decoupling is deliberate: if the required frequency of verification
tracked the detector's live precision, then every improvement to the detector would
silently reduce the frequency of demonstrated correction, and traces generated under the old
detector would teach a stale behavior. With fixed rates, the corpus remains valid as the
grounding tool improves, as occurred during this project, when the
detector was retrained on a larger pool of datasets while the trace corpus remained in use unchanged.

\paragraph{No verbal cue; magnitude carries the signal.}
Nothing in the trace-generation prompt marks a perturbed box as wrong. A verbal cue (``this box
needs correction'') would exist only during data generation and not at RL or inference time, so
teaching the model to respond to it would install a shortcut that fails at inference time. The
big tier is therefore sized to be self-evident from the crop alone, and the small tier is left
ambiguous: the demonstrator has to look and judge, which is the skill the deployed agent must
exercise without any ground truth.


\subsection{Trace generation, verification, and decontamination}
\label{sec:traces}

Traces are generated by a frontier teacher (Gemini 3.5 Flash Lite through Google, or MiniMax M3 through OpenRouter; \cref{app:access}) that is directed toward the expert labels for the image but writes
its own reasoning and tool calls turn by turn under real tool feedback. Generation is
ground-truth-directed by design, for the reason given in \cref{sec:perturbation}. Every trace then passes an independent,
cross-family \emph{verifier} (Gemini 3.5 Flash Lite through Google and GLM 5.3 Flash through OpenRouter;
\cref{app:access}) conditioned on the image and the expert labels, which rejects reasoning not
supported by what the model was actually shown (rejection taxonomy in
\cref{app:verifier}). Verification is staged rather than monolithic
(\cref{fig:tracepipeline}): a strict pass checks diagnostic correctness, FDI validity, and whether
every claim is supported by what the model was actually shown --- treating valid
\texttt{nudge\_crop} correction loops as evidence of diligence rather than as errors --- and
rejected traces are routed to a verifier-editor that repairs FDI labels, diagnosis
labels, and formatting while preserving the clinical chain of thought; the repaired trace is
re-verified before promotion. Because generation is conditioned on privileged information, traces are
scanned for \emph{directive leakage} --- the demonstrator echoing its hidden instructions in its
reasoning --- and leaking cases are excised and regenerated under a dual gate (zero-leak regex
audit + verifier re-approval); the canonical corpus contains zero leaks.

\begin{figure}[tbp]
  \centering
  \includegraphics[width=\linewidth]{fig_trace_pipeline}
  \caption{Trace synthesis, illustrated on one real trace (DENTEX image 624). (1)~A label-directed teacher operates the real tools while the shown box is perturbed. (2)~A cross-family verifier checks every trace; failures are repaired and re-verified. (3)~A leak sweep excises and regenerates contaminated traces before release.}
  \label{fig:tracepipeline}
\end{figure}



The resulting corpus (\cref{tab:corpus}) comprises 3{,}694 verified traces over 1{,}847 images
from two institutions: 1{,}847 interactive with-tools traces and 1{,}847 single-turn no-tools
traces in exact 1:1 parity --- the paired design that lets the evaluation isolate the
contribution of the tools (\cref{sec:eval}). The with-tools corpus carries 5{,}144
finding-level ground-truth annotations across cohorts (4{,}513 unique, because the 202-image
Tufts overlap cohort is contained in the 280-image Tufts all-diseases cohort), spanning caries (2{,}189), deep caries (578), impacted teeth (604), periapical
lesions (789 unique), and three further Tufts lesion classes (353); multi-finding images carry
up to 23 annotated findings, and the teacher surveys every finding on the image. Healthy scans
are included as negative controls with empty finding sets. The verifier rejected 92 traces
across three failure modes: 66 hallucinated findings on healthy scans, 15 ground-truth
contradictions (wrong diagnosis class or swapped quadrants), and 11 uncorrected spatial drifts
--- cases where the teacher diagnosed from a visibly displaced box without issuing a corrective
\texttt{nudge\_crop}. The third category indicates that the perturbation mechanism
creates judgment pressure that the verifier can audit. Across the with-tools
corpus the teacher averaged 12--13 turns and 18--30 real tool calls per trace
(\cref{tab:corpus}); the full call distribution is shown in \cref{fig:evidence} (44{,}350 attempts, 48 of them invalid; \texttt{nudge\_crop} accounts for 2{,}292).

\subsection{Anatomy of a trace: with tools vs.\ without}
\label{sec:traceanatomy}

\cref{fig:evidence} shows both halves of the paired corpus for one DENTEX image (a carious FDI
tooth 34, a single finding). The no-tools trace is one turn: a fluent, well-structured direct
diagnosis that reaches the right answer but leaves no evidence trail: its reasoning cannot be
checked against anything the model was actually shown, and the model never had the
opportunity to be wrong and recover. The with-tools trace for the same image runs 23 turns and
22 real tool calls and demonstrates the full behavioral repertoire the perturbation mechanism is
designed to elicit: the grounding box for tooth 34 was inspected, judged wrong (``the crop shows
only bone/root area \ldots the box appears to be too low''), and corrected three times with
box-relative \texttt{nudge\_crop} shifts until re-inspection confirmed the crown; a
contralateral symmetry comparison and a contrast-enhanced re-inspection followed before the
structured final answer, which matches the expert label.

The no-tools traces are retained deliberately: they teach output format and clinical vocabulary and provide the
baseline arm of every comparison. They are ground-truth-directed single-pass generations, though, closer to hindsight
rationalization than to blind discovery (\cref{sec:traces}).

\subsection{Training: SFT then GRPO with a correction-friendly reward}
\label{sec:reward}

Stage 1 (SFT) fine-tunes Qwen3.5-9B \citep{qwen2026qwen35} with QLoRA \citep{dettmers2023qlora}
on the verified with-tools traces (\cref{fig:training}), teaching the \emph{shape} of the behavior: well-formed
reasoning, well-formed tool calls with continuous parameters, and structured multi-finding final
answers. Multi-turn trajectories interleave the real crops the tools produced, and loss is
masked to assistant tokens only.

\begin{figure}[tbp]
  \centering
  \includegraphics[width=\linewidth]{fig_training_reward}
  \caption{Training. (1)~SFT on loss-masked verified traces. (2)~GRPO with live tool rollouts, a group of $K$ rollouts per image ($K \in \{1,2,4,8,16\}$), and the frozen SFT adapter as KL reference. (3)~The ground-truth-anchored reward $R$.}
  \label{fig:training}
\end{figure}

Stage 2 (GRPO \citep{deepseek2025r1}) optimizes the composite reward
\[
  R = w_{\text{acc}} R_{\text{acc}} + w_{\text{fmt}} R_{\text{fmt}}
    + w_{\text{tool}} R_{\text{tool}} + w_{\text{eff}} R_{\text{eff}},
\]
with weights $(w_{\text{acc}}, w_{\text{fmt}}, w_{\text{tool}}, w_{\text{eff}}) = (1.0, 0.2, 0.2, 0.1)$.
$R_{\text{fmt}}$ is 1 when the final answer is a valid findings object or list (an empty list is valid for a healthy scan),
and $R_{\text{tool}}$ is the fraction of attempted tool calls that had valid arguments and succeeded (1 if no tool was
called). The reward has three properties that matter for this task:

\paragraph{Ground-truth-anchored, multi-finding accuracy.}
$R_{\text{acc}}$ is a hard, non-LLM-judge match against expert labels. Predicted findings are
matched to annotated findings one-to-one by greedy highest-score-first assignment; each matched
pair scores $0.25 \cdot
\mathbf{1}[\text{quadrant}] + 0.25 \cdot \mathbf{1}[\text{position}] + 0.50 \cdot
\mathbf{1}[\text{diagnosis}]$, and the image-level score is the F1-style harmonic mean of the
matched recall and precision --- missed findings and hallucinated extra findings both score
zero, so indiscriminate
guessing cannot inflate the score. With one finding on each side this reduces exactly
to the single-pair score. This design is motivated by \citet{oralgptplus2026}, who score accuracy with an LLM-judge rubric and report
that, without a gating term on tool use, training collapses toward calling a single tool and answering without
inspection. A rule-based match against expert labels removes the judge dependence; it does not by itself rule out
other forms of reward exploitation.

\paragraph{Complexity-scaled efficiency that does not fight correction.}
A naive per-call penalty prices every tool call equally --- and therefore prices a legitimate
corrective \texttt{nudge\_crop} the same as an aimless call, directly fighting the behavior
\cref{sec:perturbation} exists to teach. $R_{\text{eff}}$ instead derives a reference budget
from the trajectory itself (6 calls per distinct located tooth), exempts \texttt{locate\_tooth}
and \texttt{nudge\_crop} entirely from per-call cost, and charges only budget overruns and
exact back-to-back repeat calls (which yield no new information), with a smooth drop-off rather
than a hard cliff.

\paragraph{Dual-adapter RL.}
The frozen SFT adapter serves as the KL reference policy on the same base model, computing the
KL penalty (the unbiased $k_3$ estimator \citep{schulman2025kl}) by adapter swapping rather than a second model in memory.

\paragraph{Memory: chunked output-head loss.}
Traces are long. A with-tools trajectory interleaves several crops and reaches 16{,}384 tokens, and the vocabulary has
248{,}320 entries, so full-precision logits for a single trace alone would occupy about 15\,GiB, before any gradient
workspace. We therefore run the transformer body once over the whole sequence, keep only the hidden states at
supervised (assistant) positions, and pass them through the frozen output head and an exact full-vocabulary
cross-entropy in chunks of $C$ positions, each chunk under activation checkpointing, so that only one chunk of
logits exists at any moment in the forward and the backward pass. Chunk losses are summed and divided by the total
number of supervised tokens. Context, targets, and objective are unchanged, so the chunking changes memory
scheduling, not what is learned: in exact arithmetic the loss and the gradient are identical to the unchunked ones,
and in finite precision only the summation order differs. GRPO uses the same scheme when it scores the log-probabilities
of the sampled tokens under the policy and under the KL reference.
